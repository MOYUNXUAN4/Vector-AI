# 10月12日：实验模型真实接入短验收

用途：验证加载、真实提示、撤警、换层、Restart和断流。不是训练集，也不用于选阈值或独立性能结论。建议单独保存为 LIVE_ACCEPT_1012，不混入 TEST1009、TEST1006 或其他冻结集。

## 开始前

- 从 fyp_Backend (3)/fyp_Backend 启动 master_server.py；确认 Falling 分支明确显示 experimental 模型 loaded，而非 disabled/unavailable。
- 使用含 LightGBM 的项目 Python。启动总控不会自动更换 Python 环境。
- Unity 打开 enableExperimentalModelWarning；三层兼容玩法，先用难度1。不是25层普通模式。
- 模型仍为阈值0.65、预测目标0.75秒；不为了触发提示降低阈值。
- 保持原灵敏度、物理、黄色预警与此前一致。不同处只有额外实验AI提示和后端自动加载。
- 正式测试开始后保留原始 telemetry 文件及 Unity Console/Editor.log。原始球轨迹 CSV 本身不能证明 HUD 实际显示过。

## 第一轮8条run

| 编号 | 条数 | 动作 | 核查 |
|---|---:|---|---|
| A | 1 | 难度1，正常三层通关 | 有效回复、无异常；记录是否出现额外实验提示 |
| B | 1 | 难度1，正常进洞换层，重点观察1→2层 | 旧层提示不带到新层；新层重新准备 |
| C | 2 | 难度1，分别前/后靠边，随后回正并继续 | 若出现真实STRONG，确认独立HUD显示与撤销；未触发也保留 |
| D | 2 | 难度1，分别左/右持续向外，让游戏球坠出 | 对照原黄色与实验提示；记录真实STRONG有无及结束清理 |
| E | 1 | 游戏运行中直接Restart，再Start新run | 不重启后端；旧run不复燃，新run正常工作 |
| F | 1 | 实验提示显示时停止master后端 | 确认预测年龄超0.3秒撤销；重启后端后必须新建Unity run |

E包含两个run，因此表中是8次操作，预计会产生9个run或更多会话文件，不以文件夹数量判定测试次数。若后台按Restart/Start分文件，保留全部，不自行合并。

F若一直未产生STRONG，不算通过“显示中断流”验收；只记做普通链路断流，之后定向补测。D或C没有报警也不要删除，更不要临时改阈值。8次操作后先检查证据，再决定是否补2–4次难度3复现，不泛泛采几十条。

## 给主代理的材料

1. 本批实际后端日志目录（包含raw.csv、已有事件/几何记录）。
2. Unity Console输出或Editor.log，保留ExperimentalModelWarning相关状态与run/序号信息。
3. 简短备注：哪次操作属于A–F；是否目视看到独立实验提示。正常/坠出标签以日志为准；运行中Restart和断流不当作正常通关。

如有录屏，可以帮助确认HUD显示和撤销；不要用录屏时间直接冒充精确几何提前量。最终核查先分开“后端输出STRONG”“Unity收到”“HUD实际可见”，合成测试和真实观测不得混算。

## 与以前的区别

以前主要收集球体/COP轨迹用于模型开发；这次主要检查模型输出能否稳定、正确地传到玩家眼前。玩家看到提示后主动恢复，会改变后续轨迹，不能宣称某次恢复一定由提示造成。模型性能对比或玩家实验应另做固定条件/对照方案，不能直接从这8次功能测试推F1或干预效果。
