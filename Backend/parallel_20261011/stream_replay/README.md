# TEST1009 read-only stream replay

`replay_real_data.py` replays only the 30 session IDs named by `baseline_fixed/config.json`, with each runtime `begin_run` / bridge `start_session` bound to the corresponding run ID in `prepared_inputs/session_manifest.csv`. It reads each session's `raw.csv` rows where `source=unity`; it does not use Wii rows, JSONL payload guesses, other cohorts, or live service inputs.

The inverse logger map is explicit in the script. `source_timestamp` becomes Unity `timestamp` in seconds. `backend_timestamp` is used only as a per-session replay receipt offset. Logger `platform_level` and `platform_tilt` become `platformLevel` and `platformTilt`. Ball position and velocity use `ball_pos_x/z` and `ball_velocity_x/z`; COP and position-derivative fields are not substitutes. Geometry IDs, active IDs, versions, validity flags, edge distance, radii, calibration flag, selected layers, scale, and run state come from their matching flattened logger columns. Blank or malformed required values remain missing/invalid.

The report separates strict default calibration handling from explicit three-layer calibration-gameplay opt-in. Feature comparison requires exact session, source sequence, and source timestamp identity, then compares all 24 features with a documented `1e-6` absolute-plus-relative tolerance. It also reports prepared-segment/runtime-generation mapping and history-start/span deltas. Probability comparisons use the same pinned artifact on the runtime feature vector and the matched prepared feature vector. Rows rejected by the model's positive-clearance/radius eligibility check remain ineligible and are reported separately.

`bridge_real_stream_parity` feeds the same mapped raw packets and logged receipt offsets to the real bridge and a separate direct `ModelWarningRuntime`, with explicit run IDs and calibration-gameplay opt-in. It compares state, validity, probability, prediction sequence, packet identity, reason, model hash, and exact probability equality on accepted rows. Synthetic fault probes are separate from real-session replay.

The timing section measures local `ingest` plus `warning` wall time only. It does not include file parsing, network/device latency, or claim end-to-end timing. The replay does not tune thresholds or report model-performance metrics. `replay_report.json` includes per-session source-file hashes before and after replay; all source files are read-only.
