# 现有提示的阶段接力显示设计

2026-10-20。设计草案，未实施、未编译或进行 Unity 视觉验收。
现有采集版本、场景、后端、模型、阈值和提示生命周期均不变。

## 1. 目的与不做的事

目的：避免玩家把“紫色估计不适用”或“橙色不再报警”误解为“已恢复安全”。
只组织已有、当前有效的状态，不推迟其撤销，不复用过期概率，不新增第四条
风险判定规则。这个显示聚合不是 LightGBM/TTE 融合预测器，也不会使模型更早触发。

首选方案：将原三个实验横幅的呈现合并为一条紧凑状态栏，列出当前有效来源；
在明确启用新呈现模式时，将已有本地黄色靠边状态一并映射到该状态栏。
不是再并排添加第四条独立横幅。原有调试 HUD 和本地黄色规则不作修改。

未来实现必须有默认关闭的新呈现模式开关；关闭时保留原显示路径。
本轮不添加开关、不保存 Inspector 或场景配置。

## 2. 当前代码的兼容性检查

已读当前工程：

- UIManager.OnGUI 分别调用 DrawExperimentalGeometryWarning、
  DrawExperimentalModelWarning 和 DrawExperimentalProximityWarning。
- 三个 Draw 方法读取 receiver.Experimental*WarningActive；这些公开 getter
  已包括各实验开关。显示层必须继续使用这些门控后的状态，不能绕过接收器。
- 本地黄色状态有 EndlessPlayerController.EdgeWarningState；UDPManager 也将其
  投影到 LastTelemetry.edge_warning_state / warning_active / visible_warning_state。
  新显示适配器应从当前局的实时本地状态取值，而不是自行重算距离阈值。
- 当前 GetEdgeHudPrompt 仅用于 showEdgeWarningDebugHud 可关闭的调试面板。
  它用瞬时 target_edge_radial_velocity<-0.05 显示 RECOVERING，不能作为
  “持续恢复完成”或“可以安全撤警”的证据，新设计不调用它推断恢复。
- 调试 HUD 的 prediction_state 在缺失时回退 SAFE，不能直接用作聚合安全标签。
- 该调试面板可关闭。因此历史 warning_active=True 是状态字段证据，不能保证
  玩家当时看到了黄色文案。七段审计没有把该字段当作渲染验收。
- 本地黄色的 bounds/半径判定与实验实际几何 q/c 不是同一真值；只复用黄色
  原状态及来源，不宣称它等价于 q<=0 或精确覆盖所有几何边界。

当前源码仅证明设计接入点存在，不证明已构建独立 Player 使用同一源码/设置。

## 3. 单一主标题和独立来源标识

输入是同一显示帧中各来源已经验证、已经启用的 active 状态。
不新增保持时间、冷却、迟滞、最少展示时长、两点确认例外或 q/c 新阈值。

| 当前有效来源 | 主标题 | 来源行 |
|---|---|---|
| 红色独立几何 active | EDGE DANGER | CURRENT GEOMETRY；其余 active 来源仍分别列出 |
| 无红色，但橙色、紫色、本地黄色至少一个 active | EDGE WARNING | 仅列出当前 active 的原来源 |
| 所有来源均 inactive/不可用 | 不显示风险主栏 | 不显示 SAFE / RECOVERED |
| 局结束、非运行态、菜单等不应显示游戏风险的状态 | 不显示运行风险主栏 | 结算/暂停等沿用原独立界面；具体生命周期需实现时核对 |

来源行使用明确且独立的标识：

- 橙色：AI PREDICTION — LightGBM。只有接收器当前 active 时才显示原 P/模型身份。
- 紫色：TTE RULE — approaching edge。只显示该来源仍有效的数据，不填旧 q 或概率。
- 黄色：CURRENT EDGE STATE — existing game rule。明确是原游戏规则，不标 AI。
- 红色：CURRENT GEOMETRY — edge danger。它不是最终坠出概率，也不声称已经掉落。

主标题的普通警告颜色保持一致，红色几何危险单独提升为红色；来源小标识保留
各自橙/紫/黄颜色，避免主标题随来源交接反复变色被误解为危险消失。
颜色不能成为唯一来源标识。AI 与 TTE 同时 active 时两者都可见，不用单一
最高优先级来源把另一个隐藏，也不把多个来源变成一个融合分数。

## 4. 接力必须由当前来源驱动

例如：TTE active → TTE不适用、本地黄色仍active → 红色几何active。
状态栏可继续显示，但 TTE 标识必须即时退出；黄色/红色凭各自当前有效状态
接力。这不是维持旧紫色，更不是保留旧 AI 预测。

橙色分数下降时，AI 标识按原接收器撤销。如果黄色仍 active，显示的是
CURRENT EDGE STATE，不显示旧 P。若没有任何有效来源，主栏立即退出，
不凭“刚才危险”补画状态。

后端断流、失效几何、旧 run/layer/platform/version 等继续按现有接收器失效关闭。
本地黄色不依赖后端，继续按它原来的本地逻辑；不得因后端断流把原黄色也清掉。
换层不能把上一平台的实验状态映射到新平台。显示层不自行修复缺失身份或排序。

## 5. 实现前必须解决的适配约束

1. 确认当前局/玩家实例与本地黄色状态的绑定及换层/新局清理路径；不能把陈旧
   LastTelemetry 或旧玩家对象的旗标当成当前局黄色。证据不足时不合成该来源。
2. 同一显示帧取一次已验证来源快照，排版只消费快照；不在 OnGUI 做网络解析、
   查询射线或修改接收器状态。缓存样式，避免重新引入高频 GUI 分配。
3. 新模式关闭时原图层和提示行为保持不变；新模式开启时避免三个旧实验横幅
   与新栏重复绘制。原 debug HUD 可保持独立，但不当作主要状态栏的前提。
4. 若实现必须改 UDP payload、receiver 校验/公开接口或本地原规则，先停下来
   说明原因；不能以显示调整名义扩展到协议/生命周期重构。

## 7. 研究评价和采集版本

原预测输出、首次算法触发和撤销时间应逐样本一致；新 UI 只改变呈现组合。
但玩家实际可见暴露可能改变，尤其原先关闭 debug HUD 时，不能宣称视觉暴露
或首次可见提示时间天然不变。须分别记录算法来源与聚合显示状态。

评价重点是来源可辨认性、是否误读为安全、有效状态交接、可见提示负担，
而非提升模型 Recall/F1 或把保持时间算作提前预测。部署仍是原 LightGBM +
独立 TTE，不是新融合模型。几何接力不能将最终坠出 FP 改成 TP。

当前多人采集继续既定版本。未来若启用新 UI，需独立 build/条件标记和收据，
不与现有提示条件混算，不根据参与者结果边采边调。本设计不要求现在重采。
