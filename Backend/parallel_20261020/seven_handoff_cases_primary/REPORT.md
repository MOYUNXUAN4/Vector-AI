# 七段接力候选案例复核与设计判断

2026-10-20。只读原开发来源；未改变模型、阈值、两点确认、提示时长、
玩法、Unity 场景、后端运行路径或当前采集版本。

## 判断

值得整理独立的“阶段接力显示语义”，但现有证据不支持马上增加第四条
告警，或通过延长紫色/橙色解决问题。原黄色在七段均有持续有效的源字段
记录，可先作为已有的当前靠边提示，而非重复创建一条新规则。

七段并不都是撤警：四段是已经报警后分数下降，一段一直低于阈值，
一段最后出现一次高分但尚未确认，另一段是等待确认后正常报警。
后三类不能用“保持旧报警”统一解决。

阶段语义应区分：AI 对未来的预测、TTE 对接近边界的估计、当前黄色
靠边状态、红色几何条件。AI 未报警或失效都不等于球体已经安全。
这是一项设计判断，不是新策略通过验收，也不提升任何模型指标。

## 固定范围与证据

沿用上一轮固定选择：31 个到达 c<=0 的片段中，七段在此前中间区域
q<=0、c>0 至少有一个橙色未报警决策。没有根据本轮结果增加或剔除案例。
q=d−2r，c=d−r；它们是规则数值边界，不是实际坠出或支撑失效标签。

- 七个不同 session，129 个连续原始 Unity 源包、34 个橙色决策。
- 原 CSV 哈希与原开发 manifest 相符；全部引用来源分析前后哈希相同。
- 源包序号连续、时间相邻间隔<=0.1 秒，run/层/平台/版本一致。
- 原始速度全部为正，没有一次 v<-0.05 的向内样本。
- 净空逐源包缩小，没有一次增加；模型未报警时 joint_recovery 均为 False。
- 原生字段全部 warning_active=True、visible_warning_state=EDGE_WARNING。
- 查询/归属/方向有效标志及 active 平台版本一致，但无法由这些标志验证
  完整查询年龄、后端接收年龄、客户端租期或实际渲染状态。

因此可以说“这些段在源数据中仍向外接近边界”，不能说“玩家完全没回正动作”
或“已实测屏幕空白”。本轮没有通过 COP 猜测意图，没有修补历史时钟对齐。

### C01/C02/C04/C05：末端分数下降，不是已恢复

模型先处于 active，后来 p<0.65，按原策略立即 raw-OFF。球虽比之前减速，
仍向外，净空继续减小，没有 joint recovery。尤其 C01 的首个未报警净空
只有 0.000236；四段距离红色数值边界的源包区间不超过约85毫秒。
不能将完整 q→c 的约0.2秒区间都算成它们的“提示空档”。

### C03：中间区域全程低分

八个决策均未 active；p 约0.369–0.609，球继续向外约0.914–1.065。
原模型报警没有出现，故“保持旧橙色”不解决该段。该 session 最终完成，
也说明当前靠边风险与最终坠出预测必须分别描述，不能强迫分数等同几何风险。

### C06：最后一次高分来得较晚

前五个决策 p约0.495；最后一个 c>0 决策 p=0.720546，但仅为 raw_on。
下个保存决策已 c<=0，原模型适用条件失败，不能凑成两次确认。
这是低分/确认时序问题，不是旧报警已开启后又被错误恢复条件关闭。
未因此建议取消两点确认，也不把高分补画成已发出的报警。

### C07：正常确认，不是撤警

第一个阶段决策 p=0.671817、raw_on；约0.05秒后 confirmed/active，之后继续 active。
如果把整段当成“模型提前撤销”，就会误判机制。本轮未改两点确认。

## 结局只作描述，不参与机制分类

七段所属 session 中五个最终 calibration_completed、两个 edge_exit。
完成不否定该时刻靠边；靠边也不证明最终必定坠出。本集合是按接力缺口
预选的困难片段，不能据此计算精确率、误报率、干预收益或新模型验收分数。
没有借当前几何状态将原最终坠出 FP 改成 TP。

## 接下来怎么做

建议先保留运行版本，做“统一现有提示的阶段含义与来源”设计，而非新增
一条独立报警。先利用现有黄色规则表达当前靠边，保持它的触发与撤销不变。
让橙色退出只表示当前模型不再报警，紫色退出只表示其估计域结束；不能让
界面把这两者暗示成整体安全或已经恢复。

若后续授权单因素显示实验，唯一变化应是现有状态的呈现/来源说明，不变
模型、阈值、原始触发时点、确认点数或源生命周期。不设置时间保持，不用
旧概率填补未知，不把几何状态标成 AI 预测。源失效时撤销依赖该源的实验提示，
原生本地黄色仍按它原来的逻辑运行。

本轮没有实施该设计或运行实验。正式 UI 接力是否有空档及是否减少困惑，
仍需客户端时序/显示证据；本轮源包数据不能替代。早期触发提前量也不会因
这种显示整理自动变好。
