# 七段新 UI 来源重放主审

2026-10-20。范围固定为原开发数据的 C01–C07，从首个 q<=0 源包至首个 c<=0 源包。只新增离线分析文件，没有改 Unity、后端、模型、阈值、原黄色规则、历史标签或采集版本。

## 结论

现有证据支持新 UI 的来源说明有实际用途：34 个保存的模型决策中，20 个未报警，而对应源包的原生 `edge_warning_state` 全部为 true。在运行上下文、当前玩家绑定与启用状态正常的条件下，新 UI 可继续显示 CURRENT EDGE STATE，不必延长 AI/TTE 或保留旧概率。

这不等于已经证明真实屏幕无空档，也不证明预测变早或准确率提高。历史数据没有完整客户端租期、暂停/报告界面、玩家对象启用状态及实际渲染记录，无法复原每一帧新 UI。

## 一处必要的口径收紧

上一轮的“原黄色全程有效”来自汇总字段 `warning_active` 和 `visible_warning_state`。它们不是新 UI 读取的玩家 `EdgeWarningState` 的同义字段。当前 UDPManager 将玩家状态与距离条件组合生成汇总状态；直接字段则是 `edge_warning_state`。

回到原始 CSV 后发现两处不同：

- C04，物理行2247、sequence1093：汇总true，本地false；下一源包约13ms后本地true。
- C05，物理行4464、sequence2166：汇总true，本地false；下一源包约21ms后本地true。

两处均为所选阶段起始包，没有同序号模型决策。不能把这两个包判为所有通道关闭，也不能声称新 UI 的本地来源在129包全部连续。进入本地true后，所选范围内未再观察到false。

## 其他通道与未知项

独立核对34个模型决策的run与source_sequence，在历史TTE重放表各找到唯一对应行，均available=false、active=false、reason=invalid_input。这是历史源规则状态，不是客户端紫色getter的实测。q<=0只是规则域边界，不能独自替代网络/接收器证据。

红色通道的实际查询有效性、年龄、身份门控及接收状态不能由c<=0推算为active，仍记unknown。本轮无法给出实际全通道空白时长、真实像素连续性或所有来源均失效的计数。未知不补成false。

## 主审与复现

主代理独立从七份原raw.csv按来源行核对序号、run状态、本地状态及34个决策匹配，并核验上一轮summary中的12项来源哈希均匹配。机械重放脚本及测试由Luna执行，结果由主代理审阅。逐包证据与输入前后哈希见本目录输出，不能用描述性包数作为模型误报率分母。

主代理最终复跑：新增重放测试7/7通过，原案例分类测试8/8通过。真实重放成功输出7案例、129包、34模型决策；13项输入前后哈希一致，七份原raw另与旧summary哈希匹配。全129包内另有35个精确TTE源快照（其中34个对应模型点），均源状态available=false、active=false，身份匹配无差异。原始物理行通过CSV reader.line_num定位；模型决策不允许重复键，时戳有限数值匹配容差1e-5秒，不用于跨时钟推断。

## 下一步

值得做一次单独的新 UI 客户端验证，但暂不切换正式采集版：验证靠边时来源增减、AI撤销只删除AI行、换层/断流按原门控撤销，以及所有来源真正失效时面板消失。该验证应单独记录显示版本；不以延长横幅填补未知，也不把显示整理当成模型性能提升。
